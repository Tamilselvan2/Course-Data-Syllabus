1. Quality Control Concepts

Quality Control (QC) is a process used to identify defects in software products and ensure that the developed software meets customer requirements and quality standards. It mainly focuses on testing and verification activities.

Objectives of QC

  • Defect Detection: Identify defects before release to reduce maintenance effort.
  • Ensuring Product Quality: Satisfies specifications and industry standards.
  • Improving Reliability: Enhances stability and reduces failure probability.
  • Reducing Maintenance Cost: Cheaper to find defects early.

Activities in QC

  • Testing: Verifying software behaves as expected.
  • Reviews: Documents and code are reviewed to detect errors early.
  • Inspections: Formal meetings to systematically identify defects.
  • Walkthroughs: Developers explain components to obtain feedback.
  • Debugging: Locating and fixing defects.

2. QA Models & Standards

McCall’s Quality Model

Evaluates software quality based on factors and criteria:

  • Product Operation: Correctness, Reliability, Efficiency, Integrity, Usability.
  • Product Revision: Maintainability, Flexibility, Testability.
  • Product Transition: Portability, Reusability, Interoperability.

Capability Maturity Model (CMM)

Measures the maturity of development processes:

  1. Initial: Unorganized, unpredictable. Success depends on individuals.
  2. Repeatable: Basic project management, previous success repeatable.
  3. Defined: Standardized, documented processes.
  4. Managed: Quantitatively measured and controlled.
  5. Optimizing: Continuous process improvement.

ISO 9000 & SPICE

  • ISO 9000: International standard focusing on documentation control, process standardization, and continuous improvement.
  • SPICE (ISO/IEC 15504): Evaluates software process capability to identify weaknesses and support improvement.

3. Methodologies & Implementation

Waterfall Model

Sequential SDLC model (Requirements → Design → Implementation → Testing → Deployment → Maintenance).

  • Advantages: Simple, well-structured documentation.
  • Disadvantages: Difficult to handle changing requirements. Testing happens only at the end.

CASE Tools

Computer Aided Software Engineering tools automate SDLC activities.

  • Upper CASE: Requirement analysis, system design.
  • Lower CASE: Coding, testing, debugging.
  • Integrated: Unified environment for whole SDLC.

1. Total Quality Management (TQM)

TQM is an organization-wide approach focused on continuous quality improvement through employee involvement, customer satisfaction, and process enhancement.

Principles of TQM

  • Customer Focus: Understanding requirements to satisfy users.
  • Continuous Improvement: Regularly improving processes.
  • Employee Involvement: Active participation in decision-making.
  • Process-Oriented Approach: High-quality processes yield high-quality products.
  • Data-Driven Decision Making: Using metrics and stats, not guesses.

2. Cost of Quality (COQ)

Total cost incurred to ensure software quality and manage defects.

Prevention Cost

Preventing defects (Training, planning).

Appraisal Cost

Evaluating quality (Testing, reviews).

Internal Failure Cost

Detected before release (Rework, debugging).

External Failure Cost

Detected after release (Lawsuits, product recalls).

3. Software Quality Metrics

Quantitative measurements to evaluate quality, performance, and efficiency.

Product Metrics

  • Defect Density: (Number of Defects) / KLOC. Lower is better.
  • Reliability: Probability of operating without failure over time.

Process Metrics

  • Defect Removal Efficiency (DRE): (Defects Removed / Total Defects) * 100. Higher means effective testing.
  • Review Efficiency: Effectiveness of catching bugs before testing.

4. Documentation Control & Maintenance

Documentation Control

Systematic management ensuring accuracy and traceability. Includes Version Control, Approval Processes, and Change Tracking. Prevents confusion and supports future maintenance.

Software Maintenance QA

  • Corrective: Fixing defects post-deployment.
  • Adaptive: Modifying to work in new environments (OS updates).
  • Perfective: Improving performance or usability based on feedback.
  • Regression Testing: Crucial step to ensure new changes don't break existing features.

1. The 7 Basic QC Tools

Fishbone Diagram

Identifies root causes systematically by categorizing contributing factors.

Pareto Chart

Uses 80/20 rule to identify the most significant defects.

Control Chart

Monitors process stability over time using Upper/Lower limits.

Histogram

Graphical representation showing frequency distribution of data.

Scatter Diagram

Shows relationship (correlation) between two variables.

Flow Chart

Represents process steps and workflow sequence.

Check Sheet

Structured form to collect and record data systematically.

2. Six Sigma (DMAIC)

Data-driven methodology to reduce defects. Goal: 3.4 defects per million.

  • Define: Identify problem and customer requirements.
  • Measure: Collect data on current process performance.
  • Analyze: Identify root causes using statistical analysis.
  • Improve: Implement solutions to eliminate defects.
  • Control: Monitor new mechanisms to sustain improvements.

3. Process Methodologies

Business Process Re-engineering (BPR)

The radical redesign of business processes to achieve massive leaps in performance, speed, and efficiency (unlike continuous improvement which is gradual).

Zero Defect

Philosophy focused on "Doing it right the first time". Emphasizes prevention over correction.

Quality Function Deployment (QFD)

Translates customer wants into technical specs. Uses the "House of Quality" matrix to map relationships.

4. Benchmarking & ISO 9000

Benchmarking

Comparing performance against industry best practices.

  • Internal: Between internal teams.
  • Competitive: Against direct competitors.
  • Generic: Best practices regardless of industry.

ISO-9000 Series

International family of quality standards.

  • ISO 9001: Requirements for QMS.
  • ISO 9002: Production & installation QA.
  • ISO 9003: Final inspection & testing.

1. Corrective & Preventive Actions (CAPA)

Corrective Action (Reactive)

Focuses on eliminating the root cause of an *existing* defect.

  1. Identify problem.
  2. Root Cause Analysis.
  3. Implement solution (e.g., bug fix, code modification).
  4. Verify effectiveness.

Preventive Action (Proactive)

Focuses on identifying potential defects *before* they occur.

  1. Risk identification.
  2. Preventive planning.
  3. Process improvement (e.g., adding automated tests).
  4. Continuous monitoring.

3. People & External Participants

People's Quality Expectations

  • Customers: Reliability, Usability, Security, Performance.
  • Developers: Clear requirements, proper tools, training support.
  • Management: High productivity, quality compliance.

Assuring External Contributions

Managing quality from outsourced teams or third-party vendors requires:

  • Supplier Evaluation: Vetting capability before hiring.
  • Contract Standards: Strict SLAs and definitions of done.
  • Acceptance Testing: Verifying deliverables before integration.
  • Audits: Ensuring they follow your organizational standards.

4. Training & Documentation Control

Staff Training & Certification

Improves technical capability and reduces manual errors. Ensures everyone understands organizational standards (e.g., Six Sigma certs, ISO certs, tech stack training).

Documentation Control Activities

  • Version Control: Tracks modifications.
  • Approval Process: Mandatory reviews before release.
  • Access Control: Restricts unauthorized modifications.
  • Change Tracking: Audit trails of who changed what and when.

1. Root Cause Analysis (RCA)

Systematic technique to find the fundamental cause of a defect, rather than just treating symptoms.

Steps

  1. Problem Identification.
  2. Data Collection.
  3. Cause Identification.
  4. Root Cause Determination.
  5. Corrective Action & Verification.

Techniques

  • Fishbone Diagram: Visual categorization of contributing factors.
  • 5 Whys: Repeatedly asking "why" to drill down.
  • Pareto Analysis: 80/20 prioritization of major causes.

2. Hazard Analysis Methods

Fault Tree Analysis (FTA)

Top-down approach. Starts with the disaster (Top Event) and maps backward to root causes using logic gates (AND/OR). Used for root cause analysis.

Event Tree Analysis (ETA)

Forward analysis. Starts with an initiating event (e.g., sensor failure) and maps forward to analyze all possible consequences. Used for outcome analysis.

3. Fault Tolerance & Failure Containment

Fault Tolerance

System continues operating despite failure. Includes:

  • Redundancy: Backup servers taking over.
  • Exception Handling: Catching runtime errors without crashing.

Failure Containment

Limits the spread of a fault.

  • Isolation: Cutting off faulty modules.
  • Partitioning: Dividing system into independent sections (e.g., payment fails, but browsing still works).

4. Defect Prevention & Risk

Defect Prevention

Implementing coding standards, testing standards, and methodologies like Cleanroom Software Engineering (formal correctness verification) and PSP/TSP (Personal/Team Software Process).

Risk Identification

Recognizing potential problems affecting schedule, cost, or quality.

  • Technical Risks: Design complexity, tech stack failures.
  • Project Risks: Cost overruns, delayed delivery.
  • Business Risks: Market competition, changing client needs.
