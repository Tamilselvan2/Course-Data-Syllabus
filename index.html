What is an Embedded System?

An Embedded System is a computer-based system designed to perform one or a few dedicated functions within a larger mechanical or electrical system. Unlike general-purpose computers, embedded systems are optimized for specific tasks and often operate under real-time constraints.

Characteristics of Embedded Systems
1. Dedicated Functionality
Designed for a specific application only. A microwave controller only controls cooking.
2. Real-Time Operation
Must respond within a fixed time. Airbag deployment must react instantly.
3. Resource Constraints
Limited memory, processing power, and battery. Software must be optimized.
4. High Reliability
Expected to operate continuously without failure (ventilators, industrial automation).

Embedded Processor Technology
15 Marks

Processor technology is the foundation of embedded systems. The processor executes instructions, controls peripherals, and manages communication between software and hardware.

1. General Purpose Processor (GPP)

Designed for a wide variety of tasks. Flexible, programmable, software-based.

Examples: ARM, Intel, RISC processors

Advantages: Easy to update, reusable, multitasking

Disadvantages: Higher power, slower than dedicated hardware

2. Single Purpose Processor

Hardware specifically designed for one application. ASIC-style.

Examples: Hardware encoder/decoder circuits

Advantages: Very fast, high efficiency, low power

Disadvantages: No flexibility, expensive redesign

3. Application Specific Processor (ASIP)

Optimized for a specific domain. Middle ground between GPP and ASIC.

Examples: DSP processors, Graphics processors

Applications: Audio processing, Image processing, Communication

IC Technologies
  • Full Custom VLSI — Entire chip from scratch
  • Semi-Custom ASIC — Standard cells & gate arrays
  • Programmable Logic (PLD) — FPGA, CPLD
🔄
The Infinite Loop
Very Important

Embedded systems don't "exit" to an OS. The main logic must run continuously from power-on to power-off.

void main(void) { hardware_init(); // Set up ports, timers, clock while(1) { // The infinite loop (Super-loop) read_sensors(); process_data(); update_actuators(); } }
💡 Why Infinite Loop?

1. Continuous monitoring of sensors
2. Continuous control of outputs
3. No program termination while powered ON

📐
MISRA C Guidelines

Critical rules to prevent undefined behavior in C for safety-critical systems.

❌ BAD (Violates MISRA C)
// Causes memory fragmentation! char* buffer = (char*)malloc(10);
✅ GOOD (Complies with MISRA C)
// Fixed allocation at compile time static char buffer[10];
  • No dynamic memory (malloc/free)
  • Variables must be initialized before use
  • Use fixed-width integers (uint32_t, not int)

The Build Process — C Code to Hardware
Guaranteed Question

The exact pipeline of how C code becomes hardware behavior:

📝

🔗

Combines object files & resolves external references (libraries).
📍

Assigns absolute physical memory addresses. Crucial — embedded systems have no dynamic OS memory.
💾

Memory Testing (15 Marks)

Verify RAM integrity by writing bit patterns and reading back:

  • Address Bus Test — Detects addressing errors & shorts
  • Device Test — Checks overall chip functionality

What is Embedded Linux?

A customized version of Linux designed specifically for embedded devices. Optimized for small memory, low power, real-time performance, and dedicated functionality.

Examples:

  • Smart TVs & Routers
  • Automotive infotainment
  • Industrial controllers
  • IoT gateways
✅
Why Linux for Embedded?
  • Open Source — Free, modifiable source code
  • Small Footprint — Only required modules included
  • Stability — Runs continuously without crashing
  • Hardware Support — ARM, MIPS, x86, RISC-V
  • Security — Access control, process isolation
🎯 Exam Question

Linux Kernel Architecture — 5 Subsystems
Most Repeated

The kernel is the core part that directly interacts with hardware and manages system resources.

1. Process Scheduler

Determines which process executes next. Handles CPU allocation, task prioritization, and context switching.

2. Memory Manager

Manages RAM allocation. Handles virtual memory, paging, memory protection, and cache management.

3. Virtual File System (VFS)

Common interface for different file systems. Supports EXT4, FAT, NFS. Provides file access abstraction.

4. Network Stack

Handles TCP/IP protocol, packet routing, socket communication. Essential for IoT and networking.

5. Device Drivers

Interface between hardware and OS. Handles peripheral control, communication, and interrupt handling.

Linux Startup Sequence

Most repeated question. Boot order:

  1. Power ON
  2. Bootloader (U-Boot)
    Initializes CPU, RAM, Flash. Loads kernel into RAM.
  3. Kernel Loading
    Kernel image copied to RAM, execution begins.
  4. Kernel Initialization
    setup_arch() configures interrupts, timers, mounts root FS.
  5. Init Process
    /sbin/init or systemd starts all services.
  6. Application Execution

What is a Real-Time System?
Most Important Unit

A system where the correctness of operation depends not only on logical correctness but also on the time at which the result is produced. The system must respond within specified timing constraints.

🔴 Hard Real-Time

Deadlines MUST be met. Failure may cause catastrophic damage.

Examples: Airbag controller, Pacemaker, Missile guidance

🟠 Soft Real-Time

Occasional deadline misses are acceptable.

Examples: Multimedia systems, Video streaming

Foreground / Background System
Foreground Tasks

High priority, time-critical, interrupt-driven. Examples: Sensor monitoring, Emergency response.

Background Tasks

Low priority, non-critical, execute when CPU is idle. Examples: Logging, Display updates.

Working: Foreground interrupts execution → Background runs during idle → Foreground always gets preference.

🔄
Context Switching
Very Important

The process of saving the state of the currently executing task and restoring the state of another task. Enables multitasking in RTOS.

What is Saved:

  • Program counter
  • CPU registers
  • Stack pointer
  • Task state (in TCB)
📋 Steps

1. Save current task context → 2. Update task state → 3. Scheduler selects next task → 4. Restore new task context

⚔️
Preemptive vs Non-Preemptive Kernel
Repeated Question
Non-Preemptive (Cooperative)
  • Task runs until completion or yield
  • Other tasks cannot interrupt
  • Simple implementation
  • Low overhead
  • Poor responsiveness
  • Bad task can freeze system
Preemptive
  • Higher priority can interrupt immediately
  • RTOS scheduler forcibly switches
  • Fast response
  • Better real-time performance
  • Complex implementation
  • Context switching overhead
🎯 Exam Tip

Preemptive is essential for hard real-time systems. Non-preemptive is suitable for simple, low-cost controllers.

📊
Scheduling Algorithms
Most Repeated

The scheduler decides which task executes next based on criteria: CPU utilization, throughput, waiting time, response time, deadline satisfaction.

1. FCFS
First Come First Serve. Tasks execute in arrival order. Simple but long waiting time.
2. Round Robin
Each task gets a fixed time slice. Fair scheduling but context switching overhead.
3. Priority Scheduling
Higher priority tasks execute first. Fast critical response but starvation possible.
4. EDF
Earliest Deadline First. Dynamic — task with nearest deadline gets highest priority.
5. Rate Monotonic Scheduling (RMS)

Fixed priority scheduling. Shorter periodic tasks get higher priority. Optimal fixed-priority algorithm for periodic tasks.

AspectRMSEDF
PriorityStatic (fixed)Dynamic (changes)
ComplexitySimpleComplex
CPU UtilizationLess efficientBetter utilization
🔄
Priority Inversion
Highly Repeated

Occurs when a high-priority task is blocked by a low-priority task holding a shared resource. A medium-priority task may further delay execution.

⚠️ Scenario

Task L (low) locks resource → Task H (high) requests same resource → Task H blocked → Task M (medium) preempts L → H waits indefinitely

Problems: Missed deadlines, reduced reliability, unpredictable timing

🔧
Priority Inheritance (Solution)

The low-priority task temporarily inherits the higher priority of the blocked task, allowing it to finish quickly and release the resource.

  1. Low-priority task owns resource
  2. High-priority task blocked
  3. Low task gets temporary high priority
  4. Resource released quickly
  5. Priority restored to original

Advantages: Prevents indefinite blocking, improves predictability, better real-time performance.

🔒
Semaphores & Mutual Exclusion
Extremely Important

A semaphore is a synchronization mechanism used to control access to shared resources. Ensures only one task accesses a critical section at a time.

Types:
  • Binary Semaphore — 0 or 1, used for mutual exclusion
  • Counting Semaphore — Multiple resources (e.g., printer pool)
// Mutual Exclusion Pattern wait(semaphore); // Request resource (lock) /* Critical Section */ shared_counter++; signal(semaphore); // Release resource (unlock)
☠️
Deadlock

A condition where multiple tasks wait indefinitely for resources held by each other.

Necessary Conditions (ALL must be true):

  1. Mutual Exclusion
    Only one task can use resource
  2. Hold and Wait
    Task holds one resource, waits for another
  3. No Preemption
    Resources cannot be forcibly removed
  4. Circular Wait
    Tasks form circular dependency
🔧 Prevention

Resource ordering • Timeout mechanisms • Banker's Algorithm

💬
Inter-Task Communication (ITC)
Very Important
Message Queue

Stores multiple messages in FIFO order. Larger storage capacity.

// FreeRTOS Example QueueHandle_t queue = xQueueCreate(10, sizeof(int)); xQueueSend(queue, &data, portMAX_DELAY); xQueueReceive(queue, &buffer, portMAX_DELAY);
Mailbox

Stores single message only. Simple, lightweight communication.

Shared Memory

Multiple tasks access same memory. Fastest communication method but requires mutex protection.

Event Flags

One task sets a flag, waiting task receives signal and resumes. Efficient for ISR-to-task signaling.

AspectMessage QueueMailbox
CapacityMultiple messagesSingle message
StorageLargerSmall
OrderFIFO supportedSimple communication
⚡
Interrupts & ISR

A signal that temporarily stops current execution and transfers control to Interrupt Service Routine (ISR).

Types:

  • Hardware Interrupt — Generated by external hardware (keyboard, sensor)
  • Software Interrupt — Generated by software instructions
📋 Handling Steps

1. Interrupt occurs → 2. Context saved → 3. ISR executed → 4. Context restored → 5. Task resumes

ISR must be: Short, Fast, Efficient

⏰
Clock Tick & Memory
Clock Tick

A periodic timer interrupt (e.g., every 1ms) — the "heartbeat" of the RTOS. Allows scheduler to evaluate delays and timeouts.

High tick frequency: Better responsiveness but higher CPU overhead.

Memory Requirements

RTOS avoids dynamic allocation (malloc/free) because it causes fragmentation leading to crashes. All stacks and queues must be statically allocated.

StaticDynamic
Fixed at compile timeAllocated at runtime
PredictableRisk of fragmentation
Safer for RTOSFlexible but dangerous
🔄
Scheduling Reentrancy

A reentrant function can be safely executed by multiple tasks simultaneously without data corruption. It can be interrupted, called by another task, and resumed safely.

✅ Reentrant Function
int add(int a, int b) { return a + b; // Only local variables }
❌ Non-Reentrant
int counter = 0; // Global variable! void increment() { counter++; // Race condition risk }

Communication Models in IoT

Client requests data, server responds. Example: HTTP communication.

MQTT vs CoAP Protocols
Very Important
MQTT

Message Queuing Telemetry Transport

Lightweight messaging protocol for IoT.

Features:

  • TCP based
  • Publish/Subscribe model
  • Low bandwidth & power
  • Broker required

Architecture: Publisher → Broker → Subscriber

CoAP

Constrained Application Protocol

Lightweight web transfer for constrained devices.

Features:

  • UDP based
  • REST architecture
  • Low overhead
  • No broker needed

Methods: GET, POST, PUT, DELETE (like HTTP)

TransportTCP basedUDP based
ModelPublish/SubscribeRequest/Response
