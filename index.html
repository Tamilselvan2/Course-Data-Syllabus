QC vs QA, McCall's Model, CMM, SPICE, inspections, walkthroughs, and the Waterfall model.

🛡️
Quality Control (QC) vs Quality Assurance (QA)
Very Important

QC is product-oriented and reactive — it focuses on testing and verification to identify defects. QA is process-oriented and proactive — it sets up processes so defects don't happen in the first place.

Quality Control
  • Product-oriented
  • Reactive — finds existing defects
  • Testing, reviews, inspections
  • Goal: detect defects before release
Quality Assurance
  • Process-oriented
  • Proactive — prevents defects
  • Process definition, standards, audits
  • Goal: build quality into the process
📐

Product Revision

SPICE (ISO/IEC 15504)

Software Process Improvement and Capability Determination:

  • Level 0 — Incomplete
  • Level 1 — Performed
  • Level 2 — Managed
  • Level 3 — Established
  • Level 4 — Predictable
  • Level 5 — Optimizing
💡 Exam Tip

CMM has 5 levels (1-5). SPICE has 6 levels (0-5). Don't mix them up.

Waterfall Model & SQA
Hidden Topic

Linear sequential SDLC: Requirements → Design → Implementation → Testing → Deployment → Maintenance.

⚠️ The SQA Catch

Testing happens only at the end. If a core design flaw is found during testing, almost everything must be scrapped. Modern SQA prefers Agile / V-Model where every phase has a corresponding testing phase.

🔀
FSM-Based Testing in Web Applications

Finite State Machine (FSM) testing models how an application transitions between states based on user actions.

E-commerce Example: Browsing → Cart → Payment Gateway → Order Confirmed. FSM maps every possible transition to ensure unexpected actions (like hitting "Back" during payment) don't crash the system.

Cost of Quality (COQ)
Most Repeated

Total cost incurred to ensure quality and manage defects. Split into Cost of Conformance and Cost of Non-Conformance.

🛡️
Prevention Cost
Cost of Conformance
Prevention Cost

Expenses to prevent defects before they occur.

  • Employee training
  • Quality planning
  • Process improvement
  • Standards development

Key insight: Higher prevention cost reduces future failure costs dramatically.

🔍
Appraisal Cost
Cost of Conformance
Appraisal Cost

Expenses related to evaluating and testing quality.

  • Software testing
  • Inspections & reviews
  • Audits

Identifies defects before release.

🔧
Internal Failure
Cost of Non-Conformance
Internal Failure Cost

Costs when defects are found before delivery to customers.

  • Rework
  • Debugging
  • Retesting
  • Scrap cost

Cheaper than external failure, but still expensive.

💥
External Failure
Cost of Non-Conformance
External Failure Cost

Costs when defects are discovered after release.

  • Customer complaints
  • Warranty support
  • Product recalls
  • Reputation damage

Most expensive. Always prioritize prevention.

COQ
Distribution
Prevention (10%)
Appraisal (20%)
Internal (30%)
External (40%)
📈 Relationship

Increasing prevention and appraisal activities reduces internal and external failure costs exponentially.

QA Activities: Regression testing, change management, documentation updates, configuration management.

🧰
7 Basic QC Tools
Very Important
1. Fishbone Diagram
Ishikawa diagram. Identifies possible causes of a problem by category.
2. Pareto Chart
80/20 rule. 80% of problems from 20% of causes. Prioritizes critical issues.
3. Histogram
Frequency distribution of data values. Shows defect patterns.
4. Control Chart
Monitors process stability with UCL, LCL, and Central Line.
5. Scatter Diagram
Shows relationship between two variables. Identifies correlations.
6. Flow Chart
Graphical workflow representation. Identifies bottlenecks.
7. Check Sheet
Structured form for collecting and recording quality data systematically.
📝 Exam Recall

Fishbone + Pareto + Histogram + Control Chart + Scatter + Flow Chart + Check Sheet

📉
Six Sigma — DMAIC

Goal: 3.4 defects per million opportunities.

  1. Define
    Problem, goals, and customer requirements
  2. Measure
    Collect data on current performance
  3. Analyze
    Identify root causes statistically
  4. Improve
    Develop and implement solutions
  5. Control
    Monitor to sustain improvements
🎯
Zero Defect Philosophy

Emphasizes "doing it right the first time" to eliminate rework.

Principles:

  • Do it right the first time
  • Prevention over correction
  • Every employee is responsible for quality
⚠️ Limitation

Difficult to achieve perfectly; requires strong organizational commitment.

🏭
Business Process Re-engineering

Radical redesign of business processes for massive performance leaps (not gradual improvement).

Steps: Process Identification → Analysis → Redesign → Implementation → Monitoring

Adv: Improves productivity, reduces complexity.

Disadv: High cost, employee resistance, risk of failure.

🏠
QFD — House of Quality

Quality Function Deployment converts Voice of the Customer into technical specifications.

Components:

  • Customer requirements (WHATs)
  • Technical requirements (HOWs)
  • Relationship matrix
  • Competitive analysis
📊
Statistical Process Control (SPC)

Uses statistical techniques to monitor and control processes.

Variation Types:

  • Common Cause — Natural, normal process behavior
  • Special Cause — Abnormal, identifiable issues

Tools: Control charts, histograms, sampling techniques.

🏆
Benchmarking Types
  • Internal — Between departments in same org
  • Competitive — Against direct competitors
  • Functional — Similar functions, different industries
  • Generic — Best practices regardless of industry
📜
ISO 9000 Series

International quality management standards:

  • ISO 9001 — QMS requirements
  • ISO 9002 — Production & installation QA
  • ISO 9003 — Final inspection & testing
  • ISO 9004 — Quality management improvement

Principles: Customer focus, leadership, process approach, continuous improvement, evidence-based decisions.

🔬
Modern QC Tools
  • Affinity Diagram — Groups ideas into categories
  • Tree Diagram — Breaks objectives into sub-tasks
  • Matrix Diagram — Shows factor relationships
  • PDPC — Identifies possible failures & preventive actions
  • Arrow Diagram — Task sequence & dependencies (CPM)

Defect Control
& Analysis

RCA, defect prevention, fault tolerance, safety assurance, FTA/ETA, and risk identification.

🔬
Root Cause Analysis (RCA)
Very Important

Systematic problem-solving to identify the fundamental cause of defects, not just symptoms.

Steps in RCA
  1. Problem Identification
  2. Data Collection
  3. Cause Identification
  4. Root Cause Determination
  5. Corrective Action
  6. Verification
RCA Techniques
  • Fishbone Diagram — Categorize causes visually
  • 5 Whys — Repeatedly ask "Why?" until root cause is found
  • Pareto Analysis — 80/20 principle to prioritize causes
💡 Example

Symptom: Web app crashes. Why? DB lock. Why? Poor SQL. Why? No training. Root Cause: Lack of developer training.

🛡️
Defect Prevention Methodologies
  • Coding Standards — Consistent, readable code rules
  • Reviews & Inspections — Early defect detection
  • Testing Standards — Consistent test procedures
  • Training Programs — Skill improvement
  • Process Improvement — Continuous analysis

Advanced:

  • Cleanroom — Formal methods, correctness verification
  • PSP — Personal Software Process for individuals
  • TSP — Team Software Process for collaboration
⚡
Fault Tolerance & Failure Containment

Fault Tolerance Techniques:

  • Redundancy — backup components
  • Error Detection — validation checks
  • Recovery Mechanisms — restore normal state
  • Exception Handling — manage runtime errors

Failure Containment:

  • Isolation — separate faulty modules
  • Partitioning — independent sections
  • Backup Systems — continue operation
  • Monitoring — detect abnormal conditions
⚠️
Safety Assurance & Damage Control

Safety Assurance Activities:

  • Hazard Identification
  • Risk Assessment
  • Safety Testing
  • Safety Documentation

Damage Control:

  • Backup & Recovery
  • Emergency Shutdown
  • Incident Response

Fault Tree (FTA)Event Tree (ETA)

🔑 Logic Gates

AND Gate: Output fails only if ALL inputs fail.
OR Gate: Output fails if ANY input fails.
